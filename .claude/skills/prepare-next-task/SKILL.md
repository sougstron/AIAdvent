# Prepare next task

Навык создаёт новый активный снапшот из текущего, не меняя старый.

## Запуск

Из любого места внутри репозитория:

```sh
.claude/skills/prepare-next-task/prepare_next_task.sh
```

Без аргумента берётся наибольший существующий номер `tree/task-N` и создаётся
`N+1`. Чтобы намеренно оставить разрыв в номерах, передайте ровно один
положительный номер, который больше текущего максимума:

```sh
.claude/skills/prepare-next-task/prepare_next_task.sh 17
```

Других флагов и режимов у помощника нет.

## Что происходит

1. Корень репозитория определяется через Git.
2. Активный номер читается из объявления в `docs/CurrentTask.md` и сверяется с
   наибольшей числовой папкой `tree/task-N`.
3. Текущий снапшот копируется через `cp -a` целиком: обычные и скрытые файлы,
   симлинки, права и весь `target/` сохраняются буквально. Ничего не
   пересобирается и не исключается.
4. Точечно обновляются активное объявление и инструкция о текущем коде в
   `docs/CurrentTask.md`, предложение об активном снапшоте в `AGENTS.md`,
    allowlist релизного бинарника в `.gitignore`; старый номер добавляется в
   архив, если его там ещё нет.
5. Метаданные сначала рендерятся во временные файлы. При ошибке публикации
   новый снапшот удаляется, а уже заменённые метаданные откатываются.

## Когда помощник откажется

Помощник ничего не меняет, если:

- аргументов больше одного или номер не является положительным целым;
- явно заданный номер не больше последнего;
- активный номер в `docs/CurrentTask.md` не равен наибольшему `tree/task-N`;
- новый путь уже существует (файл, папка или симлинк никогда не
  перезаписываются);
- обязательные строки метаданных отсутствуют, дублируются или противоречат
  друг другу;
- в `.gitignore` уже лежит неполный пятистрочный allowlist для нового номера.

Проверки запускаются отдельно и работают только во временных fixture-репозиториях:

```sh
.claude/skills/prepare-next-task/test_prepare_next_task.sh
```
