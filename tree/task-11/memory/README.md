# Память агента — три слоя, три папки

Здесь лежит то, что агент помнит. Слои физически разделены: у каждого своя
папка и свои файлы, поэтому вопрос «какие данные попали в этот слой»
решается `cat`-ом, а не догадками.

| папка | слой | что хранит | время жизни |
|-------|------|------------|-------------|
| `short/` | краткосрочная | текущий диалог: тема, договорённости этого чата | до `/new` или загрузки другой сессии |
| `working/` | рабочая | данные текущей задачи: вводные, ограничения, результаты | до `/mem task <имя>` |
| `long/` | долговременная | профиль, решения, знания | не истекает |

Имя файла = область слоя: `short/<id сессии>.json`, `working/<задача>.json`,
`long/profile.json`. Формат — JSON: `{"layer","scope","records":[{"key",
"value","turn","source","reason"}]}`, где `source` — кто положил (`user` или
`extractor`), а `reason` — почему запись оказалась именно в этом слое.

Корень памяти выбирается так: `ASK_MEMORY_DIR` (или `--memory-dir`), иначе
папка снапшота рядом с бинарником (то есть вот эта), иначе `~/.ask6/memory`.

Полное описание модели и способы проверки — в `../README.md`, раздел
«Модель памяти».
