# Можно ли поставить на сервер MoE-модель поумнее? (2026-10-11)

Повод: в чате qwen3:1.7b на вопрос по корпусу отвечает «I do not have access…»
и пересказывает названия инструментов вместо того, чтобы их вызвать.

## Что измерено

Один и тот же набор: 10 вопросов из `docs/control.json` (id 1,3,5,8,11,14,17,20
— ответ есть в корпусе; 22,24 — нет), оценка по машинно проверяемым `must` /
`wrong`.

**A. Агент сам вызывает docs-инструменты** (`server/tool_eval.py` — те же
`docs_list/read/search`, что подключает TUI). Кандидаты запускались на том же
iGPU через тот же образ llama.cpp (Vulkan, `-ngl 99`, `-c 16384`); на время
теста chat-контейнер останавливался и потом был поднят обратно.

| модель | архитектура, Q4_K_M | правильно | вызвал инструменты | скорость (prefill / decode) |
|---|---|---|---|---|
| qwen3:1.7b (сейчас) | dense 2B, 1.3 GB | 2/10 | 7/10 | ~1100 / ~35 tok/s |
| granite-4.0-h-tiny | MoE 7B-A1B, гибрид с Mamba, 3.9 GB | 0/3, остановлен | да | ~150 / 14; при длинном контексте выдаёт `????…` |
| LFM2-8B-A1B | MoE 8B-A1.5B, 4.7 GB | 3/10 | 2/10 | ~125 / 4.7 (не влезает в 4 GiB VRAM) |

**B. Тот же qwen3:1.7b через RAG-конвейер проекта** (`ask --rag-eval
--rag-eval-modes base,mcp`, embeddings через home-server):

| режим | полные ответы (из 8) | честный отказ (из 2) | время на вопрос |
|---|---|---|---|
| base (поиск + 4 чанка в промпте) | **6/8** | **2/2** | ~4 с |
| mcp (модель сама читает PDF) | 1/8 | 0/2 | ~3 с |

## Выводы

1. Маленькие MoE, которые влезают в текущий бюджет (4 GiB VRAM, свободно
   ~8 GiB ОЗУ), не помогают: Granite на Vulkan ломается при длинном контексте,
   а LFM2 медленнее в 7 раз и отвечает по памяти, не вызывая инструменты.
2. Главная проблема не в размере модели, а в режиме работы. Если 1.7B должна
   сама выбирать и вызывать инструменты, она с этим не справляется. Если поиск
   делает код, а модели остаётся прочитать 4 чанка, получается 8/10 за ~4 с.
3. По-настоящему умная MoE (Qwen3-30B-A3B-Instruct-2507 IQ3_XXS ~12 GB или
   gpt-oss-20b ~12 GB) с текущей памятью не помещается. Нужно ~12–13 GiB:
   либо остановить VM 103 `paintux-test` (8 GB), либо добавить ОЗУ. Ожидаемо
   CPU+iGPU, ~10–15 tok/s на генерацию и десятки секунд на промпт в 3.5k
   токенов. Это ещё не измерено.

## Предложение (по убыванию отдачи)

1. Для `home-server` вопросы по документам отправлять через RAG-конвейер
   (`/rag` по умолчанию или автоматически, если модель из home-server), а не
   через агентный MCP.
2. По умолчанию для home-server подключать только docs MCP вместо пяти
   серверов: промпт станет меньше (~3.5k → ~1k токенов), а выбор инструмента —
   проще.
3. Баг со скриншота: `/rag compare` идёт в `localhost:11434`, потому что
   `rag_provider` по умолчанию `local`, даже когда залогинен только
   home-server. Нужно по умолчанию брать home-server, если локальной Ollama нет.
4. Только если нужна именно умная модель в свободном чате: выделить
   ~13 GiB (остановить VM 103 или добавить ОЗУ) и провести тот же
   `tool_eval.py` на Qwen3-30B-A3B-2507 и gpt-oss-20b.

Повторить замер: `python3 server/tool_eval.py http://HOST:PORT --key KEY --model ID --ids 1,3,5,8,11,14,17,20,22,24`.
